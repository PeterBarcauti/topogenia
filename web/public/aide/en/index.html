      Chapter 1Overview

      1.1What Topogenia is for

      Topogenia maps the processes of an organisation as they really happen: who does what, in what order, with which documents, in how much time. The resulting map supports two readings at once:

      • waste: waits, re-entries, reminders, rework, switching from one tool to another;
      • automation: what software already does on its own, and what could be automated.

      You can draw a map by hand, very quickly, or have an artificial intelligence assistant propose one from a narrative, notes or a document. Each step can carry a sheet (purpose, procedure, tools, duration), documents and pain points.

      1.2Modes and confidentiality

      This manual describes Desktop mode: Topogenia runs on its user's Windows computer, its data stays in the user's Windows profile and the interface opens in the browser. A Server mode, for a team, has been announced.

      Nothing leaves the computer: no telemetry, no automatic update, no font or image loaded online. There are two exceptions. Both are off by default, a person chooses them, and only for a project whose classification is allowed in the AI settings (a single list for both):

      • the AI assistant, when the administrator has chosen a connector that calls a model and someone sends a request (chapter “The AI assistant”);
      • the online voices of the presentation, when you have chosen them. It is then not Topogenia, but the browser, that sends the text of the subtitles to its maker (Microsoft for Edge, Google for Chrome). This text is everything the presentation says: among other things pain points, names of lanes, what the names of the documents say and the presentation comments. The question is asked the first time the voice is used (see “Subtitles and voice”).

      1.3Concepts

      Concept Definition
      Project A described process, with its maps, its sheets and its translations. It has a short code of 3 to 6 letters (for example LEAVE), unique and permanent.
      Map The drawing of the process, in lanes. The root map carries the name of the project; a step can have its own detailed map.
      Lane A horizontal band per actor: a person or a role, a department, or a system (software that acts on its own).
      Step A box on the map: task, wait, start, end, or gateway diamond (decision, parallel, inclusive).
      Arrow The passage from one step to the next, with an optional label (“yes”, “no”).
      Sheet The description of a step: purpose, procedure, tools, frequency, duration, documents.
      Document An output produced by a step, or an input received from outside. Each step that uses an output is one use of it.
      Pain point What prevents a document from being used as it is, with the time lost per month.
      RACI Who is responsible (R), accountable (A), supports (S), is consulted (C) or informed (I) for each step.
      Value stream The figures of the map, calculated from a few entries: throughput, work, lead time, workload, FTE.
      Code Each object has a readable, permanent code: LEAVE-C02 for a lane, LEAVE-E004 for a step, LEAVE-I001 for a pain point.

      1.4Help

      The Help button in the top bar opens a menu of three lines, present on every page of the application:

      • Online help (key F1) opens the Topogenia help in a new browser tab;
      • Keyboard shortcuts (key ? on the map) opens the key reference in a window laid over the page: nothing is placed on the diagram;
      • Check for updates opens the versions page of the website in the browser (see “Knowing a new version exists”). This third line is shown only to the administrator, and only if the links to the website have not been hidden: without it, the menu has two lines.

      The online help holds the content of this manual, to read on screen:

      • the table of contents, on the left, follows your reading and leads to each chapter and each section;
      • the search, at the top, finds a section by its words, with or without accents (“/” or Ctrl+K to go there);
      • a click on a screenshot enlarges it; each section has its own link, to keep or to pass on.

      The help opens in the language of the interface: in French for an interface in French, in English for all the other languages. A link at the top of the help switches from English to French, and from French to English.

      The key reference answers the question “which key does that?” without leaving your work. It lists the real keys of the map, arranged by use: Moving around, Selecting, Changing the map, Display, Presenting, Help. It is drawn from the list of commands of the application: a key added to the keyboard appears in it, a key that does not exist does not. The “Changing the map” section is marked “For the facilitator of the project”: a contributor and a reader see the same list, but cannot use all of it. Esc closes the window and gives the focus back to where it was; outside a map (the list of projects, for example), the Help menu shows the same keys. The chapter “Keyboard shortcuts” of this manual is its copy.

      Chapter 2Installing and starting

      2.1Getting Topogenia

      There are two versions, identical in use:

      • Microsoft Store: search for “Topogenia” in the Store, then “Install”. Updates come through the Store.
      • Portable version: from the topogenia.com website, “Download” button. Extract the ZIP file into a folder of your own (for example Documents\Topogenia); nothing is installed. Extract a new version in place of the old one; the data is not in this folder and does not move.

      The portable version is not signed: the first time you start a downloaded copy, Windows may show “Windows protected your PC”. “More info”, then “Run anyway” starts the application.

      The two versions do not share their data: to move from one to the other, export each project as a .topogenia package, then import it on the other side (chapter “Files, exports and exchanges”).

      2.2Knowing a new version exists

      What the application does. Topogenia never goes looking on the internet: it asks neither the website nor the Store, and downloads or installs nothing. It knows two things about itself, the number of its version and the day it was released. To find out whether a newer version exists, it is therefore the browser that goes to look, when you ask: “Check for updates” opens the versions page of the website in a new tab. That page compares your version with its own list and tells you whether you have the latest; if not, it shows the version that is available, with its download and its SHA-256 fingerprint. The number of your version is written in the part of the address that the browser keeps to itself: the website receives an ordinary visit, without the local address of your computer. The full address, number included, does stay in the history of the browser, which the synchronisation of your account (Edge, Chrome, Firefox…) copies to the publisher of the browser if you have turned it on.

      Why. So that the promise “Nothing leaves the computer” (see “Modes and confidentiality”) stays true, and you still know when to update. Nothing is sent until you click.

      Where.

      • the Help menu, last line: Check for updates (hovering shows the installed version and its day);
      • the account menu, at the top right, the same line, just before “Quit Topogenia”;
      • the home page, a discreet line under the banner, once the version is at least 90 days old: “This version dates from…”, with the link “See whether a newer one exists” (it opens the same page) and a cross to close it.

      The reminder comes only from the date of the version: it does not know whether a newer version exists, it invites you to look. Once closed with the cross, it comes back only after 90 days; the day it was closed is kept by the browser, not in your projects. If the browser refuses to keep it, the line is closed for the visit only.

      According to the version.

      • Store version: “Check for updates” opens the Topogenia page in the Microsoft Store, which does the updates itself. The home page never shows a reminder.
      • Portable version: the versions page of the website; download the new ZIP and extract it as described above. The data does not move.
      • Server mode: the same page, for the administrator only (see “Roles”).

      IT can hide all these links (the menu line, the reminder and the “Template gallery” of the home page): they do it with the operating setting described in the operating documents. The rest of the application does not change.

      The steps.

      1. Open the Help menu, then Check for updates: a tab opens on the versions page.
      2. Read on the page whether your version is the latest. If not, download the new one (portable version) or let the Store take care of it (Store version).
      3. If the line “This version dates from…” is on the home page, its link does the same; the cross closes it for 90 days.

      2.3Starting

      Double-click Topogenia.exe (portable version) or choose Topogenia in the Start menu (Store version). The application opens its data file, then opens the default browser on itself.

      It then runs in the background, shown by its icon near the clock, in the notification area (sometimes under the “^” arrow). A click on this icon opens its menu:

      • Open Topogenia: opens the application again in the browser, for example after you have closed the tab;
      • Quit Topogenia: stops the application, once what is being typed has been sent (see “Quitting”).

      Starting it a second time while the application is running does not start another one: it simply opens the browser again on the one that is running.

      You do not type the address of the application by hand: only the browser opened by the application gets in. Another Windows account on the same computer cannot access it.

      2.4Quitting

      • In the interface: the account menu, at the top right, then “Quit Topogenia” and the confirmation.
      • Or the icon near the clock, “Quit Topogenia”.

      Everything is saved as you type: there is never a “Save” button to press on a map or a sheet. An entry in a sheet is sent a moment after the last keystroke; an entry that cannot be sent (the shortest duration above the longest, for example) stays waiting, flagged under its field.

      Both ways wait for what is being typed before stopping the application, so a keystroke made just before is not lost. They differ only when an entry cannot be sent:

      • The account menu refuses to quit and says so in the page: the application stays open, with the entry to correct in front of you.
      • The icon near the clock has no page to say so. It waits 5 seconds at most for the entry to be saved; if it is not, a Windows box asks “Quit anyway?”. No, the default choice, leaves the application open; Yes stops it, and the entry that was waiting is lost.

      A form to validate is different: the form of a document (an output, an input from outside, added or changed), the facilitator's question, the label of a photo in the “Analysis” panel, a presentation comment typed and not yet sent, and the dialogs that save what you type in them (project properties, translations, the sentence of the map summary, the AI settings). What you type in it is sent only when you click its button (“Save the document”, “Send the request”…); nothing sends it for you. If such a form is open and changed when you quit:

      • The account menu says so in its confirmation (“An open form is not saved: what is typed in it will be lost.”); its button becomes “Quit anyway”. Cancel, the default choice, takes you back to the form.
      • The icon near the clock asks at once, without waiting, “An open form is not saved: what is typed in it will be lost. Quit anyway?”. No, the default choice, leaves the application open: save or cancel the form, then quit again. Yes stops it without that form.

      A form opened but left as it was asks nothing; nor does a dialog that is closed or saved.

      Closing the Windows session also stops the application cleanly.

      The account menu has three lines: the interface language, Check for updates (see “Knowing a new version exists”; absent if the links to the website are hidden) and Quit Topogenia, always the last.

      2.5Data and backups

      The data is in the user's Windows profile, in %LOCALAPPDATA%\Topogenia\ for the portable version (the Store version has its own folder, specific to its package):

      Item Content
      data\topogenia.db The data file
      backups\ The automatic backups
      logs\ The technical log, kept 30 days; it holds only codes, never content

      A backup is made automatically the first time the application starts each day, one per day of the week (seven at most, replaced the following week), and before each update of the data file. If one day the file cannot be opened, the application offers at startup to restore one of these backups; the replaced file is kept alongside, not erased.

      2.6The interface language

      The account menu, at the top right, offers “Interface language”: eighteen languages, including French, English, Spanish, German, Italian, Portuguese, Polish, Turkish, Chinese and Japanese. This choice applies only to the menus and messages; the language in which the maps are shown is the language of the process (chapter “Languages and translations”).

      Chapter 3The home page and projects

      3.1The home page

      The home page brings together:

      • Describe a process: opens the map of the last project so you can complete it; as long as no project exists, it offers the starts (see below);
      • Open a file…, Import a .topogenia package…: create a project from a file (chapter “Files, exports and exchanges”);
      • Describe with AI: opens the assistant to propose a complete project from a narrative or documents;
      • New project: offers the same starts, the blank map first;
      • the Projects list, the Who is taking part list and the Recycle bin.

      Creating a project is reserved for the administrator: “Open a file…”, “Import a .topogenia package…”, “Describe with AI” and “New project” are shown to the administrator only. In Desktop mode, the person at the computer is the administrator.

      The starts. A start is a way to begin: a menu gathers them, in this order, and shows only those that are possible:

      1. Sample project (Desktop mode only);
      2. Template gallery, which opens in the browser, on the website (absent if the links to the website are hidden; see “Starting from a gallery template”);
      3. Blank map…, the “New project” form (see “Creating a project”);
      4. Describe with AI, the assistant;
      5. Open a file…, the door for a template or a collection downloaded from the gallery.

      For the administrator who has no project yet, the main button “Describe a process” is no longer greyed out: it opens this menu (hovering says “Choose how to start”). With projects, it opens, as before, the map of the project put forward, and it is New project, now a menu button, that offers the starts, “Blank map…” first. The buttons “Open a file…”, “Import a .topogenia package…” and “Describe with AI” in the header of the column do not change.

      The Sample project is a fictitious leave request project, already described, to discover a complete map (lanes, decisions, detailed map, sheets, documents, pain points). As long as no project exists, the home page also presents it on a card. In Desktop mode, it stays offered in the menu when projects exist. If its code (LEAVE) is already taken, by a project or by the Recycle bin, it takes the first free code (LEAVEA, then LEAVEB…); a message gives the code (“Sample project LEAVEA created.”) and the map of the sample opens: two clicks lead from the first start to a complete map. It is deleted like any project. The illustrations in this manual show it.

      In Server mode, nothing changes for someone who is not an administrator: the main button stays greyed out without a project, with the sentence that announces the invitation of the facilitator.

      3.2Creating a project

      “New project” (administrator) offers the starts; Blank map… opens the form. It asks first for what is essential, the name then the short code, and folds the rest under More options.

      The code follows the name. The short code is the prefix of all the codes of the project (PUR-E004) and it is permanent. As you type the name, the application suggests a code a fraction of a second after the last key, with the note “Suggested from the name.”. The rule fits in one sentence: one word gives its first six letters, two words three letters of each, three words or more their initials, words of fewer than three letters (“of”, “to”) being left out; if that code is already taken by a project or by the Recycle bin, the first free code is suggested. Examples: “Recruitment” gives RECRUI, “Leave request” gives LEAREQ. The suggested code can be corrected freely: as soon as you type in the code field, it no longer changes with the name and is never replaced. If you empty it, it stays empty: a suggestion comes back only if you then change the name, and it is then for the new name. A name with no letter from A to Z (“2026”, a non-Latin script) or too short (“HR”) gives no suggestion: the field stays empty and you type your code.

      Field Rule
      Name The name of the project in the language of the process. First field of the form.
      Short code 3 to 6 capital letters, unique and permanent (for example PUR). Suggested from the name, editable.

      Under More options (folded; nothing mandatory is hidden there):

      Field Rule
      Language of the process The language in which the process is written, that of the interface by default; the other languages will be its translations.
      Translate the name into… Adds the translations of the name.
      Description Optional: the scope, the trigger, the result.
      Shared folder (OneDrive) Optional: the folder where the documents of the process live.
      Classification Internal (by default), Confidential or Strictly confidential: shown in the application and printed on the exports.
      Members The people of the team, by their Windows login, with their role.

      “Create the project” opens its map, empty, with a first lane “Actor 1”. If the application refuses the code at creation (it was taken in the meantime), the message says so and the form stays open.

      3.3The project list

      Each row of the list gives the code, the name, the classification, the number of maps and steps, and its commands: open the map, Members, Delete….

      Delete asks you to type the project code, then moves the project to the Recycle bin: it is no longer visible, but can be restored for 30 days (“Restore”). After that, it is permanently erased with all its maps, sheets and documents. “Delete permanently” erases it at once; its code becomes free again.

      As soon as there are projects, a Filter the projects field (“Code or name”) sits at the head of the list. It keeps the projects whose code, name shown or name of origin contains each of the words typed, in any order, all in the same one of these three texts (“leave payroll” finds “Payroll of the leaves”), ignoring accents and capitals; the counter becomes “3 of 12”, and “No project matches.” appears when nothing fits. Esc empties the field and gives the whole list back. The filter works on the list already shown: nothing is sent to the server, and it changes neither the project put forward nor the Recycle bin. To search inside a project, open a map and use “Search”.

      The project as PDF (see “Map exports”): every member exports it, but the sheets of the document are those their role reads: the draft of every sheet for the facilitator (and the administrator); the draft of the sheets they can fill in and the latest validated version of the others for the contributor; the latest validated version only for the reader, a sheet never validated having no page. The maps, the RACI matrices and the action plan are the same for everyone.

      The action plan (see “The action plan”): every member sees every line, the same total of hours and the same overdue lines. Only “Edit the plan” and the Status button depend on the role: the facilitator (and the administrator) has them on every line, the contributor on those whose receiving sheet they fill in, the reader on none; they see the status without changing it.

Only tools depend on the role, because they are in the sheet: the reader finds those of the last validated version, and nothing from a sheet never validated; the contributor finds those of the draft of the sheets they can fill in (a step assigned to them, a lane that is theirs), and those of the last validated version elsewhere; the facilitator (and the administrator) finds those of the draft of every sheet. Example, in the sample project: step LEAVE-E010 “Fill in the form” has a sheet “to be specified”, with no validated version, and the tool “Form”: the facilitator finds it, the reader does not. Everyone finds the document “Request form”. A step without content has no tool. Someone who is not a member of the project finds nothing.

      3.5Project properties

      “File” then “Project properties…” (or a click on the classification, in the header) opens:

      • the Classification;
      • the Sharing group of the documents, the name of the group of people who can read the documents of the project (set here by the facilitator, 100 characters at most); it is repeated on the box of each document of a sheet (see “Documents and pain points”);
      • the Working day (hours), from 1 to 24 h, 7 by default: it turns lead times into working days;
      • the Hours per FTE and per month, from 1 to 744 h, 151.67 by default: they turn the workload into full-time equivalents.

      4.1The map screen

      The header, from left to right: the logo (back to the home page), the File menu, the name and code of the project, its classification, Members, then the language of the process, Translations, the gear icon of the AI settings (administrator) and the account menu.

      The ribbon, by group:

      At the bottom right of the map: zoom in and zoom out, the “Back to the start of the map” button and the mini map.

      4.2The map summary

      Next to the title of the map, in the header, an “i” icon holds its summary: one sentence that says what the map shows, who does what, from the trigger to the result. Each time a map opens, at every level, the sentence shows in a bubble under the title; it folds away at the first click or after a few seconds. Hovering over the icon shows it again; a click opens the summary window: its sentence, who wrote it and when, and, in orange, “The map has changed since this summary” when the map has been changed since then. Moving a step does not make a summary out of date; changing a label, an arrow or a lane does.

      The facilitator writes the sentence by hand (“Edit”, 200 characters at most), erases it, or has it rewritten by the AI. File > AI assistant > “Summarise the maps” asks the assistant for a sentence for each map that has no summary or whose summary is out of date, detailed levels included. The sentences arrive as a list in the panel: you keep, correct or drop each one, then “Save the summaries kept” saves them. Nothing enters the project without this review. The “Show the summary when a map opens” box in the summary window turns off the bubble on this computer.

      The summary is translated like the other texts: through the workbook of the “Translations” dialog or through “Translate the process”. It follows the project in the .topogenia package and the .pmap copy, and opens the Markdown export and the report, under their title, as long as it describes the map as it is.

      4.3Moving around

      A map can be larger than the window. Two gestures put it back in order: Show all and Back to the start of the map.

      Show all shows the whole map in the window. The button is at the bottom right, next to the zoom; the key is Shift+1 (on a French keyboard, the digit 1 at the top; on an English keyboard, the key that gives “!”). The zoom does not go past 100%: a small map stays at its size, because the texts of the steps are made to be read at 100%, and a map of three steps enlarged shows nothing more. A map too large to fit even at 20% is shown at 20% from its start; the mini-map places the rest. Opening a map always shows it at its start, as before: Show all is a gesture you make, not a setting the map remembers.

      Back to the start of the map (the next button, under the zoom) puts the view back as it was when the map opened, at 100%.

      Show all is for reading the map at a glance, or finding your bearings after a long scroll. Like V and H, the Shift+1 key does nothing when a single step is selected: a typed character then begins the name of the step (see “Keyboard shortcuts”). On keyboards where Shift+1 gives neither “1” nor “!” (Hungarian, Swiss), the button remains.

      Gesture Effect

      4.4Searching

      A search finds a word in the whole project, not only in the open map: a document or a tool named three levels down, a step you only remember by its code, a pain point whose map you have forgotten. Without it, you would have to open the detailed maps one by one.

      It opens in a panel on the right, which collapses like the others: Ctrl+F on the map (or in the BPMN 2.0 view), or the Search the project button at the head of the Display group. The button is offered to every role. The focus goes into the Word to find field; any text already typed is selected, so you type over it.

      Object Where the word is looked for
      Step Its name (in the language shown, then in its language of origin) and its code
      Lane Its name
      Document Its name, at the step that holds it (a received document is found once, at the step that holds it)
      Tool The “Tools” field of the sheet, and the tool of each line of the walk-through
      Pain point Its code and its description, whatever its state (treated ones included)
      Action The action decided for a pain point

      Not searched: the free text and the purpose of the sheet, the walk-through (apart from tools), the names of the maps, the summaries, the labels of the arrows and the owner of an action (it is a person's name). A pain point whose step has been deleted is shown nowhere, so it is not found.

      The words. Capitals and accents do not count (the English sample has no accent, so type a word in capitals): “TEAM” finds “Team schedule” and “Notify the team”; “coeur” finds “cœur”, “strasse” finds “Straße”. The word may be only the beginning or a piece of a word: “fact” finds “Facture”, as a browser's search does. Several words separated by spaces are searched together: a text is found when it holds all of them, in any order and in the same name or document (“request correct” finds “Correct the request”), and each word found is marked in it; the filter of the projects on the home page follows the same rule, in the code or in the name. There is one result per object: a step found by its name and by its code counts once.

      The languages. The search reads the language the map is shown in, then the language of origin of the project, and no other. Documents, tools and pain points have one language only, the one they were typed in: a text found in the language of origin, when that is not the language shown, carries its language code.

      What the panel shows. Under the field: the place of the current result (“3 of 12”) and the Previous (Shift+Enter) and Next (Enter) buttons. Then the results, arranged by map: This map first, then each detailed map under its name and its level. Each line carries the pictogram of its kind (step, lane, document, tool, pain point, action), the text around the word, the word marked; for a document, a tool or a pain point, the code and name of the step that carries it, and for a pain point its state. The current result is highlighted.

      The search starts 300 ms after the last key, from two characters; with one, the panel says “Two characters at least, or Enter.” (one is enough for an ideogram: Enter launches the search). It never shows more than 200 results: if there are more, the panel says so (“The first 200 of 1,234 results: narrow the search.”), and you narrow it by typing more. The results do not follow writes made in the meantime: they are read again when the text changes and each time the panel opens.

      Going to a result. A click on a line, or Enter in the field, opens the map of the result if it is not the open one, chooses the step and puts it in the middle of the screen. A document, a tool, a pain point or an action lead to their step; a lane, to its steps. Nothing is added to the diagram: the step found is only chosen. In the BPMN 2.0 view, a result goes back to the map, then leads to the step.

      Gesture Effect

      Enter in the field Go to the next result; after the last, the first
      Shift+Enter in the field Go to the previous result
      Click on a result Go to that result
      Esc Close the panel and give the focus back to the map

      4.5Lanes

      A lane answers the question “who does the work?”. It has a code (LEAVE-C02), a name, a type and a colour.

      • Add: the “+” of a boundary between two headers, above the first lane or below the last one. The new lane takes that place.
      • Change the order: drag the header of a lane up or down.
      • Rename: double-click its header, type the name, Enter.
      • Type: Person or role, Department, or System. Software has its own lane only if it acts on its own; a tool that a person handles is noted in the sheet of the step.
      • Colour: eight pastel tints.
      • Enlarge: drag the boundary between two headers (the “+” can be dragged too). Dragging down, the lane above gains an empty row, one more for each row height you drag; dragging up, the lane below gains one at its top. Everything below the boundary moves down as you drag; the new rows take the colour of the lane. Esc gives up; Ctrl+Z undoes a row inserted at the top. A row left empty at the bottom is not kept when the map is opened again.
      • Shrink: double-click the boundary. The last row of the lane above and the first row of the lane below are removed if they are empty (no step, and no arrow whose route passes through them); what is below moves up.

      These commands, with “Add a row at the top / at the bottom”, “Remove the empty top / bottom row”, “Translate…”, “Headcount…” (value stream) and “Delete the lane”, are in the lane menu: right-click its header. Deleting a lane that contains steps asks where to move them, or whether to delete them too.

      4.6Steps

      1. On the ribbon, choose the type of the next step (Shapes or Gateways).
      2. Double-click the target cell, in the lane of the actor who does the work.
      3. Type the name of the step (a verb and its object: “Approve the request”), then Enter.
      Type Meaning
      Step Task done by the actor of the lane
      Wait Delay during which nothing moves on
      Start Event that starts the process
      End Result that ends the process
      Decision Exclusive OR: one branch only is followed (question, yes / no)
      Parallel AND: all branches are done at the same time; a second diamond joins them
      Inclusive Inclusive OR: one or several branches as the case may be; a second diamond joins them

      A step you hover over shows “+” buttons on its sides (with the keyboard, they show when one of them has the focus): add a step after or before it in the flow, or hand over to the lane above or below, when that lane exists. The new step is linked automatically.

      While you drag a step, the cell where it will land is drawn in dotted lines; a row that dropping it would create appears in the colour of its lane.

      A step linked to nothing carries an orange “!” badge. A start with an incoming arrow, or an end with an outgoing arrow, is also flagged.

      A cadence (“every month end”) is not drawn as a diamond: it is noted in the frequency of the sheet.

      4.7Arrows

      • Link: the “Link” button on the ribbon, then a click on the starting step and a click on the arrival step. Esc stops.
      • Command bar (Ctrl+K): one line per arrow, by the codes of the steps, with an optional label after “:”. Short codes are enough: E3 > E4 : yes. “Link” (or Enter) draws all the arrows.

      The menu of an arrow (right-click) offers “Label of the flow”, “Reverse the flow”, “Share of the cases…” (exit of a decision, value stream), the start and the end of the arrow, “Automatic route” and “Delete the flow”. Arrows route themselves through the aisles between the columns; an arrow going backwards passes under the steps.

      4.8Changing the route of an arrow

      An arrow selected on its own shows a handle at each end and a small bar on each segment that can move.

      • Change the attachment side: drag the handle at one end. The four points of the step appear; the arrow attaches to the nearest one and is redrawn during the gesture. On a decision, the left point, which is its entry, and a point already taken by another exit are greyed out for the start. A simple click on a handle changes nothing.
      • Force a route: drag the bar of a segment to another aisle (between two columns) or another band (between two rows), or to the middle of an empty column or row to centre the line there. The bar snaps to the nearest position; the arrow passes there, and the rest of the route adapts without ever crossing a step.
      • Esc during the gesture gives it up. Each gesture is undone with one Ctrl+Z.
      • In the arrow menu: “Start” and “End” choose a side (“Automatic” hands it back to the drawing), and “Automatic route” removes all the choices.

      A chosen side follows its step when the step moves. A route, on the other hand, is a place on the grid: it becomes automatic again when one of the two steps of the arrow changes cell. An arrow without any choice is drawn as before.

      4.9Selecting and editing

      • A click selects a step; Shift+click, or a frame drawn on the background with the left button, selects several; Ctrl+A selects everything.
      • Rename: F2, or another click on the selected step, or type a letter directly.
      • Enter opens the sheet of the selected step; Shift+F10 or a right-click opens its menu.
      • Move: drag the step to another cell, or use the arrow keys.
      • Cut, copy, paste, duplicate: Ctrl+X, Ctrl+C, Ctrl+V, Ctrl+D. A cut step is pasted after the chosen step, or in the target cell.
      • Align: puts the steps back on a regular grid.
      • Delete: Delete or Backspace. For a detailed step, you are asked whether its detailed map goes too, or which step to attach it to.
      • Undo and Redo: Ctrl+Z and Ctrl+Y. Each operation, even a whole proposal from the assistant, is undone with a single Ctrl+Z.

      4.10Display

      The Display group of the ribbon turns on or off:

      • Codes: the code under each step and each lane;
      • Pictograms always shown: documents, pain points and duration under the steps, without hovering;
      • RACI: the roles layer (chapter “RACI”);
      • Value stream: the figures layer (chapter “The value stream”);
      • Analysis: the analysis layer and its panel; it turns off the other two layers (chapter “The analysis”);
      • Action plan: the right-hand panel that lists the pain points of the project with their plan, their hours lost and their overdue status (section “The action plan”); the same button closes it; when open, it is checked;
      • BPMN 2.0 (Alt+B): the map shown as a BPMN 2.0 diagram, read only (section “The BPMN 2.0 view” below).

      Under each step that has a sheet, a gauge shows the state of the sheet and its completeness.

      The BPMN 2.0 view

      BPMN 2.0 is the standard for drawing processes that the modellers on the market read (Camunda, Signavio, Bizagi, ARIS). The BPMN view shows the open map in this standard, to review it with a team used to it, or to see before an export what the modeller will receive. It changes nothing in the map: it is another way of looking at it.

      It opens with BPMN 2.0 in the Display group, or Alt+B, and takes the place of the map, on the same grid: each step keeps its column and its lane. The view opens at the size of the map, the step in the middle of the screen in the same place; going back to the map does the same. Each step takes the BPMN shape of its type: a circle for a start, an end or a wait, a diamond for a decision or branches, a manual task, a user task or an automated task according to its sheet and its lane, a sub-process marked [+] for a detailed step.

      • a click, Enter or Space on a step opens its sheet, read only: nothing is written in it, and a sheet in draft shows its draft there. A start, an end or branches have no sheet;
      • a double click, or Alt+Down, on a detailed step opens its detail, still in the BPMN view; Alt+Up goes back up;
      • the Details on the diagram switch shows or hides the documents and the open pain points; the choice is kept. The name of a document fits under its form on two lines at most, shortened by “…” when longer: hovering the form gives the whole name. Only the rows that carry some grow to hold them;
      • Show all, or Shift+1, fits the whole diagram in the window, at 100% at most, as on the map;
      • Export (.bpmn)… opens the export (section “Map exports”);
      • Back to the map, or Alt+B, gives the map back. Escape closes the open sheet or dialog, not the view.

      During the view, the ribbon keeps only its Level and Display groups: nothing there changes the map. You change it on the map, then come back to the view.

      Ctrl+F opens the search there, as on the map, and the Search the project button stays in the Display group. The view cannot centre a step: a result therefore closes the view, gives the map back, then chooses the step there and puts it in the middle.

      Chapter 6The sheet of a step

      6.1Opening the sheet

      A click on a step, then Enter (or “Open the sheet” in its menu): the sheet opens in a panel, to the right of the map. The panel widens by its handle (left edge; double-click to return to the original width) and folds into a strip on the right edge. Esc closes the sheet.

      The sheet opens folded, to be read at a glance: five sections, Key facts, Inputs, Procedure, Outputs and Tools (and Pain points of the step, after Outputs, when the step carries one without a document), each with its summary on the line of its title (“For each case · 10 minutes”, “2 documents”…), and the tools of the step as coloured pills. A click on a title unfolds its section. Unfold all, at the top of the sheet, unfolds them all, for this sheet and for those opened next, while the map stays open; Fold all goes back to folded sheets.

      Each entry is saved automatically: the “Saved” state shows at the top of the sheet. “Form” or “Write freely” chooses the way to fill it in.

      6.2Sheet sections

      Section Content
      Owner of the sheet The person who fills it in and validates it
      Actor Who performs the step
      Purpose Why the step exists
      Inputs The documents used: the outputs of the previous steps are offered, to tick
      Procedure The operations, one per line, with their tool and their nature (Extract, Copy and paste, Re-enter, Format, Calculate, Check, Chase, File, Send, Wait). Enter moves to the next line, Alt+Up and Alt+Down move a line.
      Outputs The documents produced, then offered as inputs of the next steps
      Tools Software, files, transactions, each in its pill: typing a name then Enter or a comma adds it, the cross of a pill removes it, Backspace in the empty field removes the last one. Under the field, “Other tools of the map” offers those of the other steps, added by a click: the same tool is thus written the same way everywhere. Common office software has its colour (Excel green, Word blue, PowerPoint orange…), the others a colour drawn from their name, always the same
      Frequency Daily, Weekly, Monthly, Month-end closing, Quarterly, Yearly, Occasional, For each case
      Duration per run The working time, in minutes
      Shortest duration, Longest duration The range around the usual duration, in minutes, each one optional: the shortest at most the duration, the longest at least the duration. A bound out of order is flagged under its field. When read: “15 minutes (10 to 25 minutes)”
      Lead time The time from the arrival of a case to its leaving the step, waits included (minutes, hours or working days)

      The actor, the purpose, the frequency, the duration and its two bounds, and the lead time are in the Key facts section.

      No section is required. The completeness is the share of the sections filled in (the lead time and the shortest and longest durations do not count).

      6.3Documents and pain points

      • Add an output: a document produced by the step, with an optional link to its location (OneDrive, SharePoint, shared folder). The document itself is never copied.
      • External input: a document received from outside the map, with the wait before receipt, in hours.
      • Medium: for each document, paper, email, spreadsheet, file, software or other. It is used to find the media breaks (chapter “The analysis”).
      • Use an output: in Inputs, tick the output of a previous step; “Other…” shows the outputs of all the steps of the map. For each document used:
        • the wait before receipt, in hours;
        • the share usable as is (%C&A): out of 100 receipts, how many can be used without completing, correcting, chasing or sending back;
        • the pain point: what prevents using it as it is, and the time lost, in hours per month. Its field is always there, under each ticked input. The pain point gets its code (LEAVE-I001) and shows on the step that produces the document;
        • its action plan, each part optional: the action decided, the owner (free text: the person need not be a member of the project) and the due date. Erasing the pain point erases its plan;
        • its status (Status button, once the pain point exists): reported at first, then in progress, implemented, adopted or dropped (see “The action plan”, which explains each status).

      The sharing group. A document is never copied: the sheet keeps only its location. Yet the next step can open it only if it is stored where that step has access. To spot this during the workshop, each document a sheet declares, output or external input, has a box Shared with the group “…”, the name being the one in the project properties (see “Project properties”); if it is empty, the box reads “Shared with the sharing group of the project”. Ticking it says: “this document is stored where the group can read it”. The mark shows on the line of the document and follows the document in the .pmap file. It is a declaration: it neither grants nor checks any right on the document, and nothing is copied or moved. It helps to see, before the workshop ends, the documents that the next step will not be able to open.

      An arrow that carries a document shows it; the documents and the open pain points appear as pictograms under the steps. The plans of all the pain points of the project are followed together in the action plan (section “The action plan” below).

      Finding a document: copy its path, open its folder

      The link of a document says where it lives. When it is a web address, the name of the document can be clicked and opens it in a new tab. When it is a path (a folder of the computer, a network share), it is written under the name. Either way, the line of the document carries what it takes to find it, for anyone who reads the sheet:

      • Copy the path: the path as it was entered goes to the clipboard, ready to paste into File Explorer, an email or a chat. For a web address the button copies the link, and for a document without a link, its name: the button says what it copies when you hover over it, and a message confirms the copy.
      • Open the folder: Windows File Explorer opens on the folder that holds the document. Topogenia never opens the document itself: you open it, from its folder, as usual. If the File Explorer window does not come to the front, it flashes in the taskbar.

      “Open the folder” exists only in Topogenia installed on your computer (Desktop mode), and for a path. On a shared server, the application runs on another machine than yours and cannot open anything on your screen: “Copy the path” stays. If the folder cannot be found, if you have no access to it or if its server does not answer, a message says so within a few seconds and nothing opens.

      A path to a network share makes Windows contact that server, as any network link you open does. In a project received from someone else, read the path, written under the name of the document, before you click.

      The name of a document is always read in full: when it is long it wraps, and the buttons go under it when the panel of the sheet is narrow.

      Where to note a pain point

      A pain point is noted where the problem is suffered: in the sheet of the step that receives the document, under that document, in its Inputs. The one who receives knows what is missing, what must be corrected or asked again. The pain point then shows on the step that produces the document, where it is fixed: in its Outputs, and as a pictogram under its box.

      Two ways lead there:

      • from the step that receives: open its sheet, tick the document in Inputs, write the pain point under it;
      • from the step that produces: in Outputs, under the document, the link Report a pain point in CODE opens the sheet of the step that receives it on its form, with the caret in the field of the pain point, even if that sheet had only been written freely. Its Inputs are unfolded for that opening only: if you had folded them, the next sheets keep them folded. There is one link per step of the open map that uses the document and whose sheet you may fill: a reader sees none, a contributor only those towards the steps they fill. A step of another map has no link: its pain point is noted from its own map. A step that no longer has a sheet (it became a start, an end, a parallel or an inclusive gateway) has none either, nor a document nobody uses yet.

      A pain point already noted is read in the Outputs of the step that produces, under its document, with its status. If you may fill in the sheet of the step that receives it, two gestures are added there: the Status button, which changes its status without leaving the sheet (the same as in the sheet of the step that receives, see “The action plan”), and the link Edit in CODE, which replaces “Report a pain point in CODE”: it opens the sheet of the step that receives on the field of the pain point, to change its description, its time lost or its plan. Without that right, the status is only read.

      The pain points of the step

      A pain point may be attached to a step without a document: no Input carries it, so it cannot be read under a document. This is the case of a project received in a .topogenia package written by hand, or of a pain point whose step that received the document was deleted. So that it does not stay hidden, the sheet of the step shows it in its part Pain points of the step, right after Outputs, folding like the others, with its count (“2 pain points”). This part only appears when the step carries such a pain point.

      Each pain point there shows its code, its status, its description, the time lost per month and its action plan (action, owner, due date). They are read only: the description and the plan are only written in the frame of a document. Only the status is changed, with the Status button, under the right to fill in the sheet of this step: the facilitator (and the administrator) always, the contributor when the step is assigned to them or when they hold its lane. The reader sees the status without changing it; the BPMN 2.0 view shows it read only. The same button is on its line of the “Action plan” panel.

      6.4The action plan

      The action plan is the list of all the pain points of the project, each with its plan: the action decided, who owns it and for when. It is in the right-hand panel, opened with the Action plan button of the Display group of the ribbon, just after Analysis. It is there to follow actions and due dates without going through an export: to know what is overdue, what has no action yet, how many hours the project loses per month, then to go straight to the step concerned. Every role has it, in the BPMN 2.0 view too.

      The button is checked while the panel is open, and closes it. It has no keyboard shortcut. The panel folds like the others; Escape closes it and gives the focus back to the map. Only one panel is open at a time: opening a sheet covers it (it comes back when the sheet closes), opening the assistant or turning on the Value stream or Analysis layer closes it, and the action plan and the search exclude each other (opening one closes the other).

      What the panel lists

      The panel lists the pain points of the whole project, whichever map is open: the main map, its detailed maps and their levels, whatever the status of each pain point. A pain point whose step was deleted is no longer in it, as on the map. The lines are in project order: the map, then the levels below it, the reading order of the steps, then the codes. It is also the order of the Excel tab (see below).

      Each line shows, on three rows:

      • the code of the pain point (LEAVE-I001) and its description;
      • the code and name of the step where the pain point shows (the one that produces the document), its map and its lane;
      • the action (or “No action decided”), the owner, the due date, the status of the pain point and the hours lost per month.

      The names of the map, the step and the lane are in the language shown, as in the export.

      At the top of the panel, three figures:

      • the total of the hours lost per month by the open pain points, for instance “5.5 h lost per month on open pain points”. It does not change with the sorts and the filters;
      • “Overdue: 1”: the number of overdue lines;
      • “Pain points shown: 2 of 3”: the lines shown, out of all those of the project.

      A pain point is open as long as it is neither implemented, nor adopted, nor dropped: it is the rule of the map, which shows open pain points as a pictogram and counts their hours as lost. The panel does not copy it, it receives it from the host.

      Overdue

      A line is overdue when its pain point is open, a due date is given and that date is strictly before today; the line then carries the “Overdue” mark beside the due date. A due date of today is not overdue. A pain point dealt with (implemented, adopted, dropped) never is, nor a pain point with no due date.

      “Today” is the calendar day of the computer of the person looking, in local time, like the TODAY() function of Excel. A due date is a day with no time zone, entered by a person in their own. In Server mode, two people in two time zones can therefore see a different overdue status the same evening: each judges on their own calendar. The day is read again each time the panel is drawn: a panel left open at midnight is right again at the next gesture in the panel (a sort, a filter) or at its next opening; a gesture on the map does not correct it.

      Sorting and filtering

      • Sort by: Project order (at first), Hours lost (largest first) or Due date (nearest first). Lines without hours or without a due date come last; among equals, the project order is kept.
      • Three filter buttons, which add up (a line must pass every one that is pressed): Open, Overdue, No action (no action is written). At first, Open is pressed: the pain points dealt with are hidden; releasing it shows them.

      The sort and the filters are kept when you close and reopen the panel in the same project, and reset when another project opens. They are never kept from one session to the next. When there is no pain point, the panel says “No pain points in this project.”; when the filters leave nothing, “No pain point matches the filters.”.

      Going to the step

      A line is a button (“Go to LEAVE-E004”). A click chooses the step where the pain point shows and puts it in the middle of the screen. If the step is on another map, that map opens and the step is chosen on arrival; the panel stays open. In the BPMN 2.0 view, the view closes first, then the line leads to the map.

      Editing the plan

      On each line you may write, the Edit the plan link opens the sheet of the step that receives the document, its Inputs unfolded, with the caret in the field of the pain point: it is where the action, the owner and the due date are entered (see “Documents and pain points”). If the step that receives is on another map (it may not be on the map of the pain point, when one of the two steps was moved), that map opens, then the sheet. The sheet covers the panel; when it closes, Escape included, the panel comes back read again once the last field entered is saved, with the line changed. If the due date entered is past, the line comes back with the “Overdue” mark.

      The link follows the right to fill in the sheet of the step that receives: it is not shown when the person may not write it (see the table below), nor when the step that receives has no content. A line without a document (part “Pain points of the step” of its sheet, see “Documents and pain points”) has no such link: its plan is only read; its status is changed with its Status button.

      Freshness

      The panel is read each time it appears: when opened, when the sheet that covered it closes, or when it appears again on another map after a sheet covered it (the sheet left open while going up a level, for example). It is not read again continuously, and going from one map to another with the panel showing does not read it again. In Server mode, what other people write is therefore seen at the next showing: closing and reopening the panel is enough.

      What each role sees and can do

      Changing the status of a pain point

      The status says where a pain point stands: it has just been spotted, an action is under way, it is done, it has become the way of working, or it was decided not to deal with it. You change it in the sheet of the step that receives the document (the Status button, in the frame of the pain point, beside the time lost), in the Outputs of the step that produces, under the pain point, and on each line of the “Action plan” panel that you may fill in. A pain point without a document changes its status in the sheet of its step, part “Pain points of the step”. It is there to keep the trace of a pain point that was lifted without falsifying the plan: without it, a pain point that was lifted could only be erased (the trace is lost) or stay open (the plan and the hours lost are wrong).

      The list of the button follows the PDCA wheel (Plan, Do, Check, Act), the loop of continuous improvement: a pain point is spotted and its action planned (Plan), the action is carried out (Do), its result is checked (Check), then the new way of working is adopted (Act). The choices come in the order of the wheel; “dropped” stands apart, after a separator, because it is not a step of the wheel. Each choice carries its help line in the list itself, read with the keyboard as with touch and by a screen reader:

      Status In the wheel Help line in the list Open?

      In progress Do action being carried out Yes
      Implemented Check action done, result to check No
      Adopted Act checked, it is the new way of working No

      An open pain point (reported, in progress) shows on the map and its hours count as lost. A pain point that is implemented, adopted or dropped leaves the map, the Open filter and the total of hours lost per month; it stays in the plan, with its date: “implemented since” the day of the change, in your computer's local time and format, never the hour. The hours lost before the change stay in the value stream snapshots already taken: the before and after can be read. A project received from a .topogenia package may carry two other statuses, “scored” (pain point assessed, action to decide) and “under review” (action being studied, not decided yet): they count as open, and the list shows them, with their help, when the pain point has one, so that nothing is lost by opening it.

      The gestures

      • The Status button shows the status alone, for instance “Reported”. A click opens it, or from the keyboard Enter, Space or Alt+↓: the list opens on the status of the moment, marked, each choice with its help line. The ↑ and ↓ arrows move in it without writing anything; a click or Enter on a choice writes it, once; Escape closes the list without changing anything and gives the focus back to the button. It is the gesture of the usual task boards.
      • From the sheet: open the sheet of the step that receives the document, in Inputs, and choose the status with the Status button. The button only appears once the pain point exists, that is when its description is saved. The choice is written at once, with no “Save” button.
      • From the panel: on the line, choose the status with its button. The choice is written at once, the plan is read again, and under the Open filter a line that is implemented, adopted or dropped leaves the list. A message says “LEAVE-I002: implemented.”, announced by screen readers, with an Undo button, which takes the focus (the status button left with the line); it stays until the panel is next read. Undo puts the status before back.
      • Reopening a pain point is choosing “reported” or “in progress”. Every move is allowed, from any status to any other: robustness comes from the history, not from an imposed path. Choosing the status it already has writes nothing.
      • No Ctrl+Z: like any write in a sheet, the change does not enter the operation log of the map. To undo it, choose the status before again, or press Undo in the panel.

      The history is never erased. Each change is added to the history of the pain point (who, when, status before, status after); no record is changed or removed, and the .topogenia package carries it. A pain point whose status has changed once is never erased again: emptying its description or unticking its use detaches it from its step and keeps it, with its history (it leaves the map and the plan), whereas a pain point that stayed “reported”, with no record but its creation, is erased with its description.

      Who can. It is the right to fill in the sheet of the step that receives (of the step of the pain point, for a pain point without a document), the same as “Edit the plan”: the facilitator (and the administrator) on every line, the contributor on those whose sheet they fill in (a step assigned to them, a lane they hold), the reader on none; they see the status and its date without being able to change it. In the BPMN 2.0 view, the status is read and the button is not offered (the sheet is read only there). In Server mode, if someone changed the same pain point in the meantime, a message says so, the panel or the sheet is read again and the person chooses again; nothing is lost.

      On copy. The status travels with the project: exporting to a .topogenia package and opening it keep it, with its history; the Excel and Markdown exports write it in the “Status” column. A .pmap copy that carries the sheets (“Save the open map (.pmap)”) keeps the status of each pain point, open or dealt with: on opening, an implemented pain point stays implemented, and the project counts the same hours; its history starts at the opening. An assistant proposal opened as a new project takes the sheets of its map of origin with the status of their pain points; it adds none of its own. Duplicate the project copies no sheet, so no pain point and no status: the duplicated project has none.

      The Excel export carries the same lines

      The “Action plan” tab of the Excel export (see “Map exports”) is built from the same list as the panel: same values, same names in the language shown, same order (project order), all statuses. It carries the exported map and its levels; from the main map, these are therefore exactly the lines of the panel with no filter. It has no “Overdue” column: a file is read again weeks later, and an overdue status frozen on the day of the export would be wrong there; Excel has its own filter on each column.

      Chapter 9The analysis

      9.1How it works

      The analysis follows the Makigami method: follow a case from one end to the other and see where it loses its time. Three causes come back almost every time:

      • handoffs: the case changes hands, and it waits in a new pile;
      • work without value for the customer: checking, correcting, re-entering;
      • media breaks: the document goes from paper to email, from email to software, and is entered again.

      The layer shows them on the map; its panel counts them, tells the lead time of a case and says where to act. Its figures come from the value stream (incoming volume, shares of the exits, durations and lead times of the sheets: chapter “The value stream”); they are recalculated each time they are displayed.

      9.2Opening the layer

      The Analysis button on the ribbon turns the layer on and opens its panel, on the right. One layer at a time: Analysis turns off the value stream and the RACI. Closing the panel turns the layer off.

      On the map:

      • the handoff arrows are marked in colour;
      • a colour band at the top of a step shows its class: green for value added, amber for necessary with no value, orange for waste;
      • a dotted step is a media break;
      • a detailed step carries a badge: the handoffs in its detail.

      9.3The tiles

      Tile What it counts Its note
      Handoffs The arrows where the case changes hands, detailed maps included The handoffs of a case on average, rework included
      Value added The share of the classified work that brings value to the customer; without the durations, the value-added steps out of all the steps The share of the work that is classified; without the durations, the steps not classified
      Media breaks The steps that receive a document on one medium and produce one on another The documents whose medium is given

      Hovering over a tile highlights its objects on the map and fades the rest; the handoffs are numbered in the order in which the case passes them. A click keeps the highlight, a second click removes it.

      9.4Classifying a step

      With the layer on, the menu of a step (right-click) offers Value for the customer:

      Class When to choose it
      Value added The customer would pay for this step: it transforms their request
      Necessary, no value The customer sees nothing in it, but a rule, a check or the tool requires it today
      Waste It serves neither the customer nor a rule: rework, a reminder, a re-entry
      Not classified Not decided yet

      A decision is classified too: it carries work. A Start, an End, a parallel or an inclusive gateway is not classified; nor is a detailed step: the steps of its detail are the ones you classify.

      9.5The medium of a document

      In the sheet, each document has its Medium: paper, email, spreadsheet, file, software, other, or not given. A step that receives a document on one medium and produces one on another is a media break: a re-entry, and a risk of error.

      9.6The case

      The section headed The case tells the lead time of a case: its average lead time, rework included, its work, and a bar that splits the lead time in three: the work, the wait after a handoff, the other wait. A sentence sums it up, for example: “It waits 8.9 d out of 9.1 d, of which 5 d right after a handoff.”

      As long as a duration or the incoming volume is missing, the wait is not split, and the section says what to ask the team. “Lead times entered” reminds you how many steps have a lead time entered in their sheet: the others count only their duration.

      9.7Where to act

      The Where to act list gives the steps where a case loses the most time: its wait, and its work when the step is classified as waste. It is ranked by the time a case loses there on average: a step that only some of the cases pass through says so (“30% of the cases”). Each row also gives its causes: the handoff (from which lane to which lane), the media break, the waste, the share received usable as is, the open pain points.

      The first three rows are shown; “See all…” shows the others. A click on a row selects its step on the map.

      The Excel exports and the report repeat these figures in the Summary: handoffs, handoffs per case, wait after a handoff, value-added share, media breaks.

      9.8Snapshots

      A snapshot freezes the indicators of the project, its main map and its details, to measure the gain later: lead time (including the wait after a handoff and the other wait), work per case, value-added share and work classified, handoffs, media breaks, rolled %C&A, hours lost, open pain points. Snapshots are in the Analysis panel, on the main map, in the Snapshots section.

      • Take a snapshot (facilitator): a label, for example “Before the workshop”, then Take.
      • Compare with now: the button of a snapshot opens a table, indicator by indicator: the snapshot, now, and the change, in green when it goes the right way, in red otherwise; the two waits are indented under the lead time.
      • Delete a snapshot (facilitator). A snapshot cannot be changed: it stays as it was taken.

      9.9The target state

      The target state is the intended process, drawn next to the current one to quantify the gain before changing anything. File > Project > Create the target state… (administrator) makes a new project, a complete copy of this one (maps, sheets, documents, pain points, members), linked to it; its indicators of today become the reference.

      In the target state, you draw the intended process: fewer handoffs, less rework, steps removed or automated. The Analysis panel shows, on the main map, the Target state section: the reference, the source project, and the table that compares the reference with the process drawn.

      Refresh the reference reads the indicators of the source project again as you see them, and replaces the reference. This is the job of a facilitator of the target state who can see the source project; otherwise the button is greyed out and the screen says why: the source project is not visible to you (one of its facilitators or an administrator can refresh), or it no longer exists (the reference stays readable).

      Chapter 10Running a Makigami with Topogenia

      A Makigami is done in a workshop: the team that handles the case, a facilitator, the map on the wall and on the screen. This chapter gives a sequence; each action points to its own chapter.

      10.1Before the workshop

      • Choose the case you follow: a request, an order, an expense claim. Say where it starts and where it ends.
      • Create the project and its lanes: one per team, person or software that touches the case (chapter “The map”). Lay down the outline of the known steps, without looking for detail.
      • Enter the incoming volume on the Start (Value stream layer): without it, the wait of a case cannot be split.
      • Print the map large for the wall (File > Export the map > Print large…, see “Map exports”).
      • If the map already carries figures, take a snapshot “Before the workshop” in the Analysis panel.

      10.2During the workshop

      One pass per question, in this order:

      1. The path: follow the case from step to step and lay down each arrow, rework included (“no: to be corrected”), with its share (chapter “The value stream”).
      2. The documents: what each step produces and receives, and on which medium (paper, email, spreadsheet…). The media breaks appear on the Analysis layer.
      3. The durations: in the sheet, the duration per run of a step and, when it varies, the shortest and the longest; its lead time, waits included.
      4. The value: classify each step, with the Analysis layer on, through the step menu: value added, necessary with no value, waste.
      5. The pain points: where a document received causes a problem (incomplete, to be re-entered), tick its use, describe the pain point and the time lost.
      6. The plan: for each pain point kept, the action, who owns it and the due date, under the pain point. Before closing the pass, open the Action plan panel (Display group) and press No action: no pain point kept should be left there.

      The wall is for discussion, the screen for entry: the facilitator records everything as the workshop goes on, and the team sees the map change.

      10.3Reading the map with the team

      The Analysis layer counts the handoffs, the value-added share and the media breaks; “The case” tells its lead time and “Where to act” ranks the steps where it loses the most time (chapter “The analysis”). For the feedback session, print the map large again with the marks of the Analysis layer: handoffs in colour, class band at the top of the steps, media breaks dotted.

      10.4After the workshop

      • Follow the plan: in a meeting, open the Action plan panel (Display group), press Overdue and sort by Due date; a click on a line leads to the step, Edit the plan updates the action, the owner and the due date (section “The action plan”); the Status button moves what is done to “implemented”, then what is checked to “adopted”. To keep a trace or share it, the Excel export adds the “Action plan” tab (map, step, pain point, action, owner, due date, status), which you can filter in a meeting, in project order; the Markdown export carries the same table. A pain point that was lifted is not erased: its status moves to “implemented” (then “adopted”), it leaves the map and the total of hours lost, and the trace stays in the plan.
      • Hand the project over to someone without the application: File > Project > Whole project as PDF… (section “Map exports”); one file with the maps level by level, a clickable contents and, as you choose, the sheets and the action plan. A reader only gets the validated sheets: send it only to people allowed to read them.
      • Draw the intended process: File > Project > Create the target state… (administrator); its Analysis panel compares the process drawn with the reference (chapter “The analysis”).
      • Measure the gain: a snapshot after the changes, compared with the one before.
      • Tell the story of the process: the assistant's report (File > AI assistant > Narrated report (Markdown)).

      Chapter 11Presenting a map

      11.1The principle

      In a meeting, a projected map is hard to read: the room does not know where to look. The presentation tells it as a story, in full screen: it follows the case from step to step, shows each step with its actor, runs a light along the arrow to the next one, and says in subtitles what there is to know. Nothing has to be prepared: everything comes from the map, its sheets and the value stream. Nothing of the map is changed: the presentation only reads; only the presentation comment of a step or of a handoff may be written while it runs (see below).

      The story goes through every step of the map, once each. Its thread is the main path of the value stream (the most likely journey of a case); without figures, it follows the arrows in the reading order. Where the map divides, it tells the other branches first, then takes up the main path again (see “When the map divides”). It opens on the whole map and closes on a summary.

      11.2Starting the presentation

      • The Present button on the right of the ribbon, or F5: the presentation opens on the whole map.
      • Shift+F5: it starts from the selected step and tells what follows it.
      • Present from this step, in the menu of a step (right click on it): the same start, but from the clicked step, not from the one that was selected before the click. The line is in the first group of the menu, after the lines that open the sheet and the RACI, and shows Shift+F5 on its right. A contributor and a reader have it as the facilitator does.

      The presentation opens paused: it waits until the room is ready. Play (the button in the middle of the bar) or Space starts the story; the arrow keys move it by hand, step by step.

      A reader can present too. The presentation fills the whole screen; if the browser refuses the full screen, it fills the window. Escape closes it and gives the map back as it was.

      11.3What the screen shows

      • The current step stands out, with a halo in the colour of its lane (a decision, by the outline of its diamond); its box says its name and its code, its lane says the actor: no banner repeats them. In a small window, at the opening and at the summary where the whole map fits on screen, a lane name too long for the height of its lane is shortened with “…”, and the name of a lane too low for a single line is hidden; its coloured border stays. The steps already seen stay half visible, the others fade.
      • The arrows all stay visible: those leaving the current step are sharp, the one the story travels lights up, the others stay in the background. The whole process stays readable.
      • The subtitle, just above the bar, says one fact at a time, and only what the map does not write: the lead time, the value class, the documents received and produced (see below), the pain points, the share of the cases of each exit of a decision, a change of medium, a handoff. What the box already shows (its work time, its number of documents) and what its shape says (a start, an end, a decision, a join) are not repeated. A fact that is not known is not said; a step with nothing to add stays on screen without a subtitle.
      • The title, at the top left, says where you are: the name of the process on the main map; in a detailed map, the step it details, with the steps you entered through before it, paler. It is written in the language shown.
      • The counters, at the top, add up the work per case and the lead time along the main path: the lead time often grows by days while the work grows by minutes only. They do not move on the steps of another branch: a case does not go through all of them. A step done in sessions adds only its share per case; the subtitle says it after the work of a session.
      • The lanes are named on the left; a mini map, at the bottom right, shows where the view is.
      • Between two steps, a light runs along the arrow, from the edge of the box it leaves; the documents passed on travel with it. After a parallel gateway, a light leaves on each branch at the same time.

      11.5Presenting at your own pace

      You may let the presentation tell the story, or speak yourself. Two buttons of the bar, each on its own, silence what it says:

      • Step messages (key E): what is said of each step, the sentences of the application or the comment typed;
      • Handoff messages (key R): what is said on the way from a step to the next.

      A message turned off is neither shown nor read by the voice; the opening and the summary are still said. With both off, the presentation is silent: when paused, drag the map by hand, double-click a detailed step to show its detail, and speak at your own pace. Turn either one on again at any time, on the map or in a detail; Play takes the story up where you are. The browser keeps this setting from one presentation to the next.

      11.6When the map divides

      The story leaves no step out. Where several arrows leave a step, it tells the other branches first and the main path last: once it moves on along the main path, it never goes back.

      • At a decision (or an inclusive gateway), each exit is told in turn. The story takes an exit, tells its steps up to the one where the branch ends or joins a step already planned, then comes back to the decision, which says the next exit (“The story follows …”). The exit of the main path comes last. An exit that goes back is only lit: the steps already seen are not played again.
      • At a parallel gateway, and at any step that several arrows leave without a gateway (the analysis counts them as a parallel split), the lights leave together on every branch. Each branch is then told one after the other, up to the step where they join.
      • Several starts: the other entries are told first, each up to the step where it joins the rest; the opening says the number of starting points. The main path comes next, from its start.
      • Steps linked to nothing are shown at the end, in the reading order, before the summary.

      Between two branches, the view comes back by itself where it should.

      11.7Choosing a branch

      At a decision, a numbered badge sits on each exit; the filled badge is the exit the story takes now. A click on another badge, or its number on the keyboard, goes at once to that exit: “and what if it is no?”. The story tells every exit anyway; the badges choose which one to show now.

      11.8Entering a detailed step

      A detailed step has its own map (see “Detailing a step”). During the presentation, a double click on it, the Show the detailed map button of the bar (it only appears on a detailed step) or the D key presents its detailed map in full screen, from its opening, with its own counters. A single click on a step shows it without entering it.

      At the end of the story of the detailed map, the presentation comes back by itself to the step of the map above, stopped, with its counters; Play takes the story up where it was. The Back to the map above button, or the U key, goes up at once. A detailed step of the detailed map opens in the same way, level by level. Escape leaves the whole presentation: the editor stays on the map it started from.

      11.9The presentation comment

      The sentences of the presentation are written by the application, from the figures of the map. For a step, you may say something else: the context, what matters to the room. That is the presentation comment of the step: one to three sentences, 500 characters at most. When a step has one, the presentation says it and subtitles it instead of its own sentences; each line written is a sentence. The comment is not in the sheet: it only serves the presentation, and it travels with the project in a .topogenia package, into a target state and, since 3.3, in a .pmap copy and a duplicated project.

      To write it, during the presentation, on the step shown:

      • the Step comment button (the pencil) of the bar, or the T key: the presentation pauses and a field opens where the subtitles stand, with the comment already written; under the field, a counter gives the number of characters typed, out of 500;
      • Enter saves it and closes the field, Shift+Enter starts a new line. Enter on a text you have not changed closes the field without writing anything;
      • Escape closes the field without leaving the presentation, and keeps what you wrote, as Enter does: nothing is lost by a reflex press. With the field open, Escape never leaves the presentation. In full screen, depending on the browser, Escape may also leave the full screen: the presentation then goes on in its window, and F gives the full screen back;
      • once saved, the step starts again at the first sentence of the comment, paused: Space resumes playback;
      • an empty field, saved, removes the comment: the step says its own sentences again.

      Commenting a whole process in one go. The field follows the step, as the notes pane of a slide show follows the slide. With the field open, click another step on the map, a step mark of the bar, or Previous step or Next step: your text is saved, the presentation moves to that step, and the field opens on it, ready for you to write. You write, you click the next step, you write: no need to close the field and open it again. Back to the start, or Next step on the last step, saves your text and closes the field, because the opening and the summary have no comment.

      The comment of a handoff. An arrow takes a comment as a step does: it is said while the light travels along it, instead of the sentence of the handoff. To write it, click the arrow on the map: the presentation shows its way, and the pencil (it is then called Handoff comment), or T, opens the field on it. The field is named by the two steps the arrow links. With the field open, it follows your clicks on the steps and on the arrows alike: you comment a step, then the handoff that follows it, then the next step, without closing the field. When several arrows leave a step together, T opens the field on the first one; click another arrow to comment that one. The comment lives with its arrow: an arrow deleted then drawn again is another arrow, without a comment. Likewise, inserting a step on a commented arrow replaces it with two new arrows, without a comment: Ctrl+Z undoes the insertion and gives the arrow back with its comment. It is translated and travels as the comment of a step does.

      While the field is open, the keys write in the field: none drives the presentation, and Play waits until the field is closed. The pencil closes the field and Leave the presentation leaves: both save your text first. To go back to the text of before, write it again, or undo your typing in the field (Ctrl+Z) before you leave it.

      If the save is refused, the message shows at the top of the screen and nothing moves: the field stays open on its step, with your text. Enter tries to save again. To give that text up, do again the gesture that was leaving the field (Escape, the pencil, a click on a step, Leave the presentation) while the message is still shown: this time it goes through without writing anything. Give the message time to show: the second click of a double click does not count. Once the message has gone, that gesture tries to save again first.

      One case apart: another facilitator changed this comment in the meantime, and the message tells you so. Enter then saves your text in place of theirs, knowingly. A gesture that leaves the field never writes over the text of someone else: it shows the message again, and the same gesture done again gives your text up.

      While a text is being saved, the field and the presentation wait for the answer, which takes an instant. If Topogenia does not answer, the field is given back to you after ten seconds, with a message.

      A comment in each language. The comment follows the rule of the other texts of the project: it has an original, written in the language of origin of the project, and a translation in each of the other languages you present in. The presentation says the text of the language the map is shown in; when there is none in that language, the step keeps its own sentences. The field always says which language you are writing in:

      • with the map shown in the language of origin, T writes the original. If you change it, its translations made by the assistant or by a workbook are removed, because they no longer match it; those you entered by hand stay. An empty field, saved, removes the comment with all its translations;
      • with the map shown in another language, T writes the translation of that language. The original is recalled above the field and does not change. An empty field, saved, removes that translation only.

      To translate all the comments at once, use the “Translations” dialog (chapter “Languages and translations”): the assistant and the workbook translate them with the other texts.

      Having the AI write them. For a map described by hand, the assistant can propose the comments of its steps and of its handoffs, and those of its detailed maps, from the maps and their sheets. Run File > AI assistant > “Presentation comments…”, or the Presentation comments tile of the assistant panel, which lets you make the request more precise (“only the Accounting lane”, “without the detailed maps”, “rewrite them all”). From the main map, it writes for the whole process; from a detailed map, for that map and what lies below it. By default, it writes for the steps and handoffs that have no comment yet, 300 at most per request. Its proposals arrive in the panel, one per step or handoff, map by map, the name of each map above its comments: keep it, correct it or drop it, then Save the comments kept, from any map of the project. A proposal that would replace a comment you typed is unticked and says so: it replaces it only if you tick it. Nothing is written before you save. The presentation then says these comments as it says yours.

      Only the facilitator of the project writes a comment; a contributor and a reader hear it when they present. Ctrl+Z does not undo a comment: you write it again.

      11.10Subtitles and voice

      The subtitles are in the language the process is shown in (chapter “Languages and translations”); each sentence stays the time it takes to read it. The Subtitles button (or C) hides them, for instance when you comment yourself.

      The Voice button (or V) reads the subtitles aloud; the story waits for the end of each sentence. While the voice speaks, the subtitles hide: the room hears the sentences instead of reading them twice; C shows them again. Turning the voice off brings the subtitles back. If no voice can say the language the map is shown in, the subtitles show as long as the voice is on, even if you had hidden them: the presentation is never silent and without text.

      The first time Voice is pressed, if the browser offers online voices, a question asks which one to use:

      • Computer voice: a synthetic voice; nothing leaves the computer.
      • Natural online voice: more natural, but the text of the sentences is sent to the browser maker (Microsoft for Edge, Google for Chrome).

      The question always shows in view: while it is open, the bar stays visible, and a black or white screen is lifted.

      The answer is kept. The setting next to the Voice button changes it: the list of voices, and the Allow online voices box. The voice chosen is kept by the browser, even after the page is reloaded, as long as it is still offered.

      The voice of the project. A project keeps one voice for each language it is presented in: the one that says it well in French, another one for English. It spares choosing the voice again at each session and on each computer, and it travels with the project: it is written in the exported .topogenia file, and found again at the import (not in a .pmap copy nor in a duplicated project).

      In the settings of the voice, the Voice of the project for this language box says whether the project keeps the voice shown in the list, for the language the map is shown in. A facilitator of the project sets it in two ways: by choosing a voice in the list, which the project keeps at once, or by ticking the box when the list already shows the right voice. Unticking the box removes it from the project: it keeps none for that language any more, and the voice goes on reading for you. A reader or a contributor has no such box; they may choose another voice: it reads for them as long as the map stays open, and the project keeps its own.

      When a presentation starts, the voice that reads is, in this order: the one you chose since the map was opened; otherwise the voice of the project for the language shown, if this computer offers it; otherwise the voice kept by the browser; otherwise the first of the list. A voice of the project that this computer does not have (another browser, another system) is left out, and nothing changes in the project. An online voice kept by the project never reads without your consent: you must have allowed the online voices on this computer, and the classification of the project must allow them (see below); otherwise a computer voice reads. Answering “Natural online voice” to the question of the first use gives that consent: the online voice of the project then reads, if this computer offers it; when the project keeps none, or keeps a computer voice, a natural voice of the browser reads for the session.

      Online voices are offered only for a project whose classification is allowed to go to the AI, the same list as the assistant (see “AI settings”). For another project, only the computer voices read, the question is not asked, and the Allow online voices box is turned off, with below it: “The classification of this project does not allow online voices.” Topogenia reads this permission when each presentation starts; until it is read, or if it cannot be, only the computer voices are offered. In Edge, a company can also turn the online voices off for everyone with a policy (ConfigureOnlineTextToSpeech): the question is not asked either. Chrome has no such setting.

      11.11What the presentation says of a document

      A document often bears a file name: “Leave_tracking_2024-03_v2.xlsx”. Such a name reads badly aloud and tells the room nothing. So the presentation says the type of the document, then what it holds, like a title: “Receives an Excel spreadsheet: Leave tracking.” The whole name stays written on the map and in the sheet.

      • The type comes from the medium entered in the sheet (“The medium of a document”) and from the extension of the name, wherever it stands in the name: “Tracking.xlsx (Leave sheet)” is an Excel spreadsheet. The media Paper, Email and Software are enough: a paper document, an email, data from software. The medium Spreadsheet says “a spreadsheet”, or “an Excel spreadsheet”, “a CSV file” when the name bears that extension. With the media File or Other, or without a medium, the extension of the name decides: an Excel spreadsheet, a CSV file, a Word document, a PDF, a Visio diagram, a PowerPoint presentation, an email, an image. Without an extension that tells a type, the medium File says “a file”.
      • The content comes from the name, from which the presentation removes what is not said: the extension, the underscores, the dates, the long numbers (five digits or more, or starting with 0), the version marks (“v2”) and the codes, that is an acronym in capitals stuck to a number (“FORM-HR-007”, “IMG_1234”). “FORM-HR-007-Leave-request.docx” is said “a Word document: Leave request”. When nothing readable is left, the type is said alone: “Receives a PDF.” A short number that goes with a word of the title is said: “ISO 9001 certificate.pdf” is said “a PDF: ISO 9001 certificate”, “Annex 2.docx” “a Word document: Annex 2”, “Report 2025.xlsx” “an Excel spreadsheet: Report 2025”.
      • An address or a path typed as a name gives its last segment only: from C:\Users\reception\Documents\Leave tracking.xlsx, the presentation says “an Excel spreadsheet: Leave tracking”. The server and the folders are never said.
      • A document whose type nothing tells is said by its title: “Receives Purchase order.”
      • Three documents at most per sentence, then “and 2 others”.

      For a document to be said well, give it a name that says what it holds and enter its medium.

      11.12The summary

      The end of the story shows the whole map, the journey lit, and says the lead time end to end for the work, the share of the work in the lead time, the handoffs and the open pain points, when the value stream knows them. A story started at a step first says the lead time and the work of this journey, those of the counters, then those of the main path.

      Chapter 12Languages and translations

      12.1Two languages

      • The interface language (account menu): the language of the menus and messages, for you alone.
      • The language of the process (list in the header, when a project is open): the language in which the maps are shown. The list shows the language of origin, the translated languages with their progress, and the others.

      A text that is not translated shows in its language of origin, in grey italics, marked “To translate”. In a language other than the origin, the structure of the map is locked: renaming an object writes its translation, never the original. To work in another language, make it the language of origin (“Changing the language of origin”, below).

      The search (“Searching”) reads the language shown, then the language of origin, and no other. Only projects, maps, lanes, steps and arrows have translations: documents, tools and pain points have one language only, the one they were typed in, and are found as they were written.

      12.2The “Translations” dialog

      The Translations button in the header opens the dialog.

      • Translate with the assistant: choose a language, then “Translate into …”. The assistant translates the whole process (detailed maps and project name included). The preview shows the translated texts in place on the map, without writing anything; “Apply” writes them, “Dismiss” gives the map back. A translation entered by hand is always kept. The presentation comments of the steps and of the handoffs are translated at the same time: the preview counts them apart and lists them under “Review the texts”, the one of a handoff marked “handoff comment” beside the codes of its two steps (they are said in a presentation, they are not shown on the map). Ctrl+Z undoes the translations of the map, not those of the comments.
      • Or with an Excel workbook, in three steps:
        1. Download the texts to translate: “Not translated”, “Not translated by hand” or “Everything”. The glossary of the project (one term a line, for example “clôture mensuelle = monthly closing”) goes with the workbook.
        2. Have the empty cells completed: by Copilot in Excel (“Copy the instruction for Copilot”), by another AI, or by hand.
        3. Bring back the translated workbook: “Choose the translated workbook…”. The report says what is saved and what is skipped.

      The workbook also carries the presentation comments, after the texts of the map: item “Presentation comment” for a step, “Handoff comment” for a handoff, named by the codes of its two steps (500 characters at most, line breaks kept: each line is a sentence said aloud).

      12.3Translating by hand

      The menu of a step, a lane or an arrow offers “Translate…”: the original text and its translation in each language of the project; “Add a language” adds one. A translation entered here is manual: a workbook replaces it only with the “Everything” choice.

      12.4Changing the language of origin

      The language of origin is the one the project is written in: it is the only one its maps are changed in (adding a step, moving, linking). In the other languages, you only translate. If the team that keeps the project alive works in another language than the one it was written in, make that language the language of origin: its texts become the originals, and those of the former language become their translations.

      A language can only become it when the whole project is translated into it: the texts of the maps, and the presentation comments of the steps and of the handoffs. The “Translations” dialog says so, under the workbook, for each language the project has translations in:

      • “Missing texts: N”: some texts are left to translate, with the assistant or the workbook. When presentation comments are missing, the line says so: “Missing texts: N, including M presentation comments”. The percentage at the top of the dialog does not count them;
      • “Missing texts: unknown”: the missing comments could not be read; the language is not offered. Close and reopen the dialog to read them again;
      • the Make this the language of origin button: everything is translated. A question explains the effect, the undo history cleared included; “Change” applies it. The project is then shown in its new language of origin.

      Good to know:

      • only the facilitator of the project can do it;
      • Ctrl+Z does not undo this change. To go back, make it again towards the former language: the texts come back as they were. The steps and the presentation comments created in the meantime must first be translated into the former language;
      • the change empties the undo history of the project, on all its maps and for everyone: what was done before can no longer be undone;
      • sheets, documents and pain points are not translated: they keep their language. Also read the glossary of the project again, which does not change;
      • once translated, the presentation comments follow without anything to do: the one of the new language becomes the original.

      Chapter 13The AI assistant

      13.1What is sent, and when

      The assistant sends to an AI model the documentation of the Topogenia formats, the schema of the project (without the accounts of the members or the authors; what you have written goes as it is, the owner of an action included), the open map, the selected steps, the request, the attached files and the previous exchanges in the panel. For a translation of the process, it also sends the presentation comments of the steps and of the handoffs that have no text yet in the language asked for. For the “Presentation comments” tile (and File > AI assistant > “Presentation comments…”), it likewise sends the comments already written on the steps and handoffs of the open map and of its detail maps, saying whether each was typed by a person or written by the AI (never a name), 300 at most: the AI does not rewrite them blindly. Nothing is sent:

      • without a connector that calls a model (by default, there is none);
      • without a request from a person;
      • for a project whose classification the administrator has not allowed.

      The content of the panel is kept nowhere: not in the data file, not on the computer, not in the log.

      13.2AI settings

      The gear icon in the header (administrator) opens “AI settings”.

      Still with AWS Bedrock, the region entered is the one the request is sent to. An inference profile whose identifier starts with global. lets AWS process the request in another region than the one of the account, anywhere in the world. To keep the processing within a zone, enter an inference profile of that zone: for example an identifier that starts with eu. for Europe.

      • “Nothing leaves” assumes a model installed on the machine. A “cloud” model offered by Ollama is computed online, at the maker of Ollama, and not on the machine: do not choose it if nothing must leave.
      • The model must be able to read a long prompt. The context of a model is the amount of text it reads at once, counted in tokens. At each exchange, Topogenia sends a long prompt: about 30,000 tokens, before the project itself. So load the model with a context of at least 64,000 tokens. With a smaller context, the model cuts the request without saying so and answers without having read the project, or refuses it. This is set in the program, not in Topogenia: in Ollama, the context length of the model; in LM Studio, the context length chosen when the model is loaded. A large context takes memory. Test the connection does not see this fault: it only sends a short question.

      The AI button on the right of the ribbon, or Ctrl+I, opens the panel.

      • The panel header gives the scope (the whole project, or the open map); a line says where the data goes.
      • The tiles offer typical requests: Create from a text or a file, Change the map, Analyse what I see, Ask a question, Presentation comments.
      • The steps selected on the map are sent with the request; you can remove the selection tag.
      • Enter sends, Shift+Enter starts a new line. “Stop” interrupts an exchange; “New conversation” starts again.
      • The paperclip attaches files: PDF, images (PNG, JPEG, GIF, WebP), Word (.docx), Excel (.xlsx), Visio (.vsdx). Five files per conversation at most.

      14.2Map exports

      • The project as PDF: all the maps of the project in one file, with, as you choose, their sheets, their RACI matrices, their value stream and the action plan. The other exports give the open map; this one gives the project as it reads from top to bottom, to hand over to someone who does not have the application (a participant without an account, a management team, an auditor) and who opens it in any PDF reader. The line is in the File menu, Project > Whole project as PDF…; every member has it, readers included, and it stays active in the BPMN view.

      The dialog first asks the Scope: The whole project (from the main map), or This map and its levels (the map shown and its detailed maps, offered only on a detailed map; the document then starts at that map, and its title page says so). Four boxes follow:

      • With the sheets, ticked at the start: one sheet page for each step that has a sheet. Under it, a warning: the sheets are those you can see, send the document only to people allowed to read them;
      • With the RACI matrix: for each map that carries RACI letters, the matrix (the steps concerned in rows, the lanes in columns); ticked at the start if the RACI is shown on the map;
      • With the value stream: the value stream pages of each map, as in the PDF of a map; ticked at the start if the layer is on, and the value stream band is then also drawn on the maps;

Create the PDF starts the task; Cancel (or Esc) stops it, and nothing is downloaded.

A clickable contents follows, one line per map, indented by level, with its page number: a click leads to the map. The file also carries bookmarks, one per map, nested like the levels, which the PDF reader shows on the left. The maps follow level by level, each under its path and, within a level, in the reading order of the steps they detail: the detail of step E002 before that of E005. After the page of a map come, if ticked, its value stream pages, its RACI matrix, then its sheets in the reading order of its steps. A map without steps has its page, which says “Map without steps.”. The action plan closes the document, in the order of the project (that of the Excel export, see “The action plan”), with the same columns; it is there only if it has at least one line.

      The classification is printed at the top of every page, in bold, and the foot carries “Generated by Topogenia”, the code of the project and “Page n of N”. The maps, the matrices, the value stream and the plan are A3 landscape; the title page, the contents and the sheets are A4 portrait. To print an A3 page on A4 paper, choose the “Fit” scale (“Fit to printable area” in some browsers) in the print window, otherwise the page comes out cut off.

      The sheets are those seen by the person who exports, by the rule that governs the screen of the sheet (see “Roles”). In the PDF the facilitator finds the draft of every sheet; the contributor, the draft of the sheets they can fill in and the latest validated version of the others; the reader, the latest validated version only, and a sheet never validated has no page for them. Under the title of a sheet is written the status that the map shows that person (“validated”, “draft”, “to review”). A step whose sheet is empty has no page: there is no “to fill in” page. The figures of the value stream follow the same rule. The maps, the paths, the RACI matrices and the action plan are the same for everyone. Two people with different roles who export the same project therefore do not get the same document; in Server mode, the server keeps a trace of the export (“project.exported”, format “pdf”) when the sheets are read, even if the person cancels afterwards. A “Strictly confidential” project can be exported, its classification printed on every page: its sheets are then readable by whoever receives the file, unlike the editable copy of the SVG image, which is refused for that level; hand the document only to authorised readers.

      The names written by the team are printed as they are: the “actor” of a sheet, and the “owner” of an action of the plan, as in the Excel export. No location of a document (path or address) is ever printed. Pain points are cited by their code (“Pain point …”), their detail being in the action plan, which holds only the pain points of the maps in the document.

      The bounds: 100 maps, 12 levels and 1,000 pages. An empty detailed map counts among the 100 maps, since it has its page. Beyond 100 maps, the dialog refuses and says what to do: choose “This map and its levels” when it offers it, otherwise first open a detailed map further down. Beyond 1,000 pages, it refuses too: from the main map it suggests unticking the sheets; from a detailed map, unticking the sheets or exporting a map further down. The maps beyond 12 levels are not in the document, which the contents says on its last line (an empty detailed map at that level is not missing). While another export runs, the dialog refuses too: “Exporting…”.

      While the task runs, the boxes are greyed out and a bar shows the progress: “Reading the maps: n”, “Reading the sheets…”, “Map i of N”, then “Writing the document: page p”. At the end the file goes into the Downloads folder, under the name “code - name of the project - project”; a notification says “Export complete: the file is in your downloads.”.

      Two differences to know. Each map is an image: its text cannot be searched or copied in the PDF reader, whereas that of the title, the contents, the sheets, the matrices and the plan can. And the page of a map is redrawn from its view, like the SVG image, and not captured from the screen as in “PDF (A3 landscape)”: a difference of detail between the two is possible.

      • PDF (A3 landscape): the whole map, with the title, the date and the classification. With the value stream layer on, a “Value stream” page is added (summary, basis of calculation, main path, check).
      • PNG image: the whole map, not only the screen, with its classification.
      • Copy the map as an image: the same image as the PNG, but put on the clipboard instead of in a file, to paste it (Ctrl+V) into an email or a slide without going through the Downloads folder. The line is in the File menu, at a click, right after “Save the open map (.pmap)”, and in the menu of the map background (right click away from any object). The image keeps the same frame, the same fonts and the same line of classification as the PNG; any reader of the project can copy it. A map larger than 4,000 px a side is reduced to fit under 8,000 px a side (the PNG goes up to 12,000): a larger image would weigh the Windows clipboard down with several hundred MB. During the copy, a notification says “Copying the image…”, then “Image copied”; the line is greyed out in the BPMN view, which is not a map.
      • Copy the selection as an image: the same gesture for a few steps. Choose the steps, right click on one of them, “Copy the selection as an image”. The image is framed tight on the chosen steps, with a margin; it shows only them, what hangs under them (frequency, RACI), the arrows whose two ends are chosen and their labels; the other steps, their arrows and their value stream cards are hidden, even inside the frame. It does not carry the names of the lanes: they are in the left margin of the map, and keeping them would leave an empty band as soon as the selection is not at the start. The line of classification sits under the image.

      The browser must allow an image to be written to the clipboard. Edge and Chrome do. Firefox does since its version 127, provided the copy follows the click closely; the image can take a few seconds to draw, and Firefox may refuse it. If the copy fails, the notification says “The image could not be copied” and offers “Export as PNG”, which produces the file instead: that of the whole map, even when the copy was of a selection. - Excel: the Steps, Links and RACI matrix tabs; with the value stream layer on, also “Value stream”, “Summary” and “Where to act”, in full-precision numbers with the origin of each value. As soon as a pain point exists on the map or on its detailed maps, an “Action plan” tab lists them all, whatever their status: map, step, lane, pain point, action, owner, due date, status and hours lost, with a filter on each column to follow the plan in a meeting. The tab carries the exported map and its levels, the Action plan panel the whole project: from the main map, they are the same lines, in the same order (project order). It has no “Overdue” column: a file is read again later, and the overdue status does not freeze in it (see “The action plan”). - Print large…: the map as a poster, on several A4 or A3 landscape pages to assemble on the wall. The dialog asks for the paper (A4 by default) and the number of pages across, from 1 to 10; the height follows from it. It gives the number of pages, the size of the poster and its scale (100%: the map at its size on screen), and first offers the fewest pages that print it at least at that size. The “With the marks of the Analysis layer” box, ticked when the layer is on, adds the handoffs, the classes and the media breaks. Beyond 100 pages, choose fewer pages across. The codes, the pictograms, the RACI and the value stream follow the display, as for the SVG image.

      Each page carries its name in the footer, A1, A2… for the first row, B1… for the next one, and its number. Two neighbouring pages share 10 mm. To assemble: trim the left margin and the top margin of each page along the cut marks, except for the first column and the first row; lay the page on its neighbours, with its edge on the lines of their margin, and tape it on the back.

      • SVG image: the map redrawn as a vector image, sharp at any size, to place in Word, PowerPoint or a web page; same frame and same classification line as the PNG. The “Include an editable copy” box, unticked by default, slips into the image the map, its detailed maps and the sheets you can see: the image then opens again through “Open a file…”. The box is unavailable for a “Strictly confidential” project. Word and PowerPoint replace the Inter font with a similar font.

      • Markdown (Mermaid): a .md file with the title, the classification and the date, the diagram of the map in Mermaid (one lane per block, one shape per type, labels in short lines, never cut), then the tables of the steps, the links and the RACI, and the action plan when the map has pain points. You can read it in VS Code and in the Markdown readers that draw Mermaid.

      • BPMN 2.0 (.bpmn)…: the map as a BPMN 2.0 file, the standard of the process modellers (Camunda, Signavio, Bizagi, ARIS…), to take it up in the tool of another team. The file follows the standard of the OMG to the letter. What BPMN does not draw (the sheet, the RACI, the value stream, the presentation comment) is written in the documentation of each element, which the modeller shows when you select it; the location of the documents is never written. The dialog offers to include the detailed sub-processes (each one then opens in the modeller) and to draw the documents and the pain points. The file is written in the language of the map shown. The classification of the project is written in the file; it does not prevent the export. The file is also offered by the Export (.bpmn)… button of the BPMN view. Good to know: Camunda Modeler and bpmn.io do not draw the lanes inside a sub-process; its steps keep their actor there, written in their documentation.

      14.3Opening a file

      “Open a file…” (home page or File menu, administrator) creates a new project, or several when the file is a template collection. The points to check (unknown columns, rows not understood, texts cut) are shown when the file opens.

      File What is read
      .pmap The light format of the maps: lanes, steps, arrows, RACI, detailed maps and translations. Readable by a person or an AI; it also opens when pasted into the dialog (for example the reply of an AI)
      .pmaps A template collection: several processes, each one a complete .pmap, gathered in a single text file. The dialog lists them, you tick the ones to create, and each becomes a project (see below). It needs version 3.4 of Topogenia
      .xlsx, .csv A table of steps: columns Step and Lane, or ID and Step, then, as you choose, Next, Flow label, Type, Time, A, S, C, I or RACI. The columns of Visio Data Visualizer and the workbook exported by Topogenia are recognised. A CSV can be separated by semicolons, commas or tabs
      .mmd, .md A Mermaid flowchart (flowchart or graph), or the first one in a Markdown document: one lane per subgraph, one type per shape (diamond: decision; circle or stadium: start or end), one arrow per link with its label. Styles are left out
      .svg An image exported by Topogenia with “Include an editable copy”; only the copy is read

      A collection. A collection (.pmaps) is a file that gathers several processes, for example all the templates of a domain (see “Starting from a gallery template”). As with a .pmap, you choose it with “Choose a file…”, drop it or paste it: the dialog recognises it and takes “Collection” followed by its name as its title, with the sentence that says the essentials: one project is created for each process ticked, and nothing is written before “Create the projects”.

      • The list. Each process is a line: its box, its name, its language, its numbers (steps, lanes, links, maps), “Points to check: n” when its author flags some, and its code. All are ticked. The “Select all” box in the header ticks or unticks everything, and “Ticked: 2 of 5” tells you where you stand. The fold “Description and points to check” of each line shows what the process tells and what is left for you to settle: these are questions, not errors.
      • The code. It is proposed free: the one of the file, or failing that drawn from the name as for a new project (see “Creating a project”). If that code is already taken, by a project or by the Recycle bin, the first free code is proposed: ACHAT taken gives ACHATA; two processes that want ACHAT get ACHAT then ACHATA. Each code can be corrected line by line (3 to 6 capital letters). “Create the projects” stays greyed out while no line is ticked or a ticked code does not have that format.
      • A process refused on its own. A process that cannot be read (a language not configured here, an invalid file) is unticked and greyed out, with its faults in a fold “Cannot be opened:”. It does not stop the others. If it is the envelope of the collection that is at fault, or if it holds more than 50 processes, the whole file is refused and the dialog says why.
      • Creating. “Create the projects” creates one project for each ticked line, in order, with “Creating 2 of 5…”. Each project is created whole or not at all; an unticked line is never sent, and “Cancel” leaves nothing behind.
      • The result. The dialog becomes “Projects created”: each project that succeeded says “ACHAT created.” and offers “Open the map”; a refused line says “Not created: …” (for example “ACHAT is already taken.” if someone took the code in the meantime), keeps its code editable and offers “Try again”. The other lines are not touched. “Close” ends the dialog.

      A file over 10 MB is refused before it is read, like any file. “Insert a file as a detailed step…” does not take a collection: it points to “Open a file…”, and you insert one of its templates on its own (see “Inserting a sub-process described elsewhere”). In Server mode, only the administrator opens a collection; they become the facilitator of each project created, and the codes are those of the whole server (see “Roles”).

      14.4Starting from a gallery template

      What it is. The gallery gathers templates of common processes (purchasing, for example): swimlane maps ready to open, which describe the most usual course of a process. A template is a starting point to adapt, never the process of a company. It comes in two forms: one .pmap file per process, and for each domain a .pmaps collection that gathers them all.

      Where it is. On the Topogenia website, not in the application: the Template gallery start of the home page (see “The home page”) opens its page in the browser. It is absent if IT has hidden the links to the website; the website then opens from the browser. The page of a domain shows each template with its image, its description, its file, its text to copy and its fingerprint.

      Why this way. The browser downloads the file: Topogenia fetches nothing from the internet, and nothing leaves the computer. A template is a readable text file, which you can read in Notepad before opening it, and each file is published with its SHA-256 fingerprint, a string of characters that changes if a single character of the file changes: it lets you confirm that the file you received is the one that is published.

      The steps.

      1. On the home page, choose Template gallery; on the website, open the page of the domain you want and download the template, or the collection of the domain. The file lands in Downloads.
      2. Check the fingerprint, optional and quick: in PowerShell, opened in the folder of the file, run Get-FileHash -Algorithm SHA256 file-name, then compare the result with the fingerprint on the domain page or with the line of the sha256.txt file (upper and lower case do not matter). If the two strings differ, do not open the file and download it again from the website.
      3. In Topogenia, Open a file… (home page or File menu, administrator), then “Choose a file…”. A single template creates one project, with the code and the name proposed in the dialog. A collection first shows its list, all the processes ticked.
      4. For a collection: untick those you do not need, correct the proposed codes if necessary, then Create the projects. The list of results says which project is created, and each opens through “Open the map” (see “Opening a file”).
      5. Adapt: the opened template is a project like any other, whose lanes you rename, whose steps you change and whose responsibilities you complete. Review it with the people who do the work: the template describes the most common case, and the adapted map is the one that counts.

      If the download is blocked. Some computers forbid downloading files. The page of each template then offers a “Copy” button, which puts its text on the clipboard: in “Open a file…”, paste it into the area “Or paste its content here”. The result is the same as with the file. A collection has no such button: download it, or copy each of its templates. The fingerprint, however, can only be checked on a saved file.

      Which version. The templates are .pmap files: a single template opens from version 3.3, a collection needs version 3.4. If the version in use is older, the versions page of the website says which one to install (see “Knowing a new version exists”).

      14.5Inserting a sub-process described elsewhere

      What it is. An overall map is often built from sub-processes that other teams described, in other projects. Rather than drawing them again, the facilitator inserts their .pmap file: it becomes a new detailed step of the map shown, with all its detailed maps. It is a copy: changing the original file afterwards does not change your map. When a newer version arrives, “Replace the detail with a file…” brings the step up to date. The two computers need no shared server: the file is enough.

      Preparing the file. In the original project, open the map of the sub-process, then File menu, “Save the open map (.pmap)”. An Excel or CSV table, a Mermaid diagram or an SVG image that carries its copy also do.

      Inserting. Four ways open the same dialog:

      • File menu > Project, “Insert a file as a detailed step…”: you choose the step after which to place the new one (or the start of the map) and its lane. As with “Insert a step after”, the step enters the flow: the arrow that left the step chosen is cut in two and linked on both sides, its label staying on the side of its origin. If you had selected an arrow before opening the menu, the dialog offers “On the flow A → B”. With nothing selected, it offers the arrow that reaches the end of the process: the step is never placed after an end, nor before a start;
      • right-click on an arrow, “Insert a file on this flow…”: like a shape dropped on a connector, the step cuts that very arrow, even one of the exits of a decision, the others staying in place;
      • right-click on an empty cell of the map, “Insert a file here…”: the step takes that cell, without an arrow, for you to link;
      • right-click on a detailed step, “Replace the detail with a file…”: its current detail goes to the recycle bin and the file takes its place.

      Choose, drop or paste the file. Before anything is written, the dialog shows what it holds (steps, lanes, links, maps, sheets), the points to check flagged by its author, and the translations left out because their language is not configured here. The label proposed is the name of the project of the file; you can change it. Ticked by default, “Take the sheets” brings the sheets with their documents and their pain points, as drafts: to review, then validate.

      What is copied: lanes with their colours, steps, arrows and their routes, RACI roles, detailed maps, summaries, translations and presentation comments. Everything arrives at once, the view centres on the new step, and a single Ctrl+Z undoes the whole insertion or replacement.

      A file in another language. A file written in another configured language than that of the project (a sub-process in English in a project in French) keeps its language: its texts are marked as written in English, and its French translations stay translations. The map shows them in French when you show it in that language.

      Limits. A map and its details fit in 12 levels, those of a .pmap file: a file too deep for the place chosen is flagged and is not inserted. A file over 10 MB is refused, and a .topogenia package is not inserted: it is imported as a project. The name of the original file is not kept on the step.

      14.6The .topogenia package

      The package holds the whole project: maps, sheets, documents, pain points and translations. It is used to move a project from one computer to another, from the portable version to the Store version, or to back it up on its own.

      A project that carries a chosen route, a map summary or analysis data (class, medium, shortest or longest duration, action plan, snapshot, target state) is written in a version of the package (2.2 or 2.3; 1.3 or 1.4 for the .pmap) that version 3.0 of Topogenia does not open. A project in which a step or a handoff carries a presentation comment, or that keeps a presentation voice, is written in version 2.4 of the package, which version 3.1 does not open. Its .pmap copy, which also carries the comments and the glossary, is written in version 1.5, which version 3.3 and later open. Without these items, the package and the copy stay readable by the previous versions.

      • Export: “Without the members and the authors” is ticked by default: neither the accounts of the members nor the authors are written in the package; what you have written stays in it as it is, the owner of an action included.
      • Import (home page or File menu > Exchange package, administrator): choose the package, then “Check the package”. The package is checked without writing anything; the preview counts its maps, lanes, steps, sheets, documents and pain points. If its code is already taken, the dialog asks for another one: all the codes of the project are then rewritten. The “Take the members of the package” box, unticked by default, also takes its members when the package carries them. “Import” creates the project.
      • Replace: the package takes the place of the project, with the same code; the current project goes to the recycle bin.
