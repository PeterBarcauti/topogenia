# 022 - En-têtes de fichiers

Statut : acceptée (date 23/10/2026)

## Contexte

La spec 0.2 impose un en-tête de deux lignes de commentaire, le nom du fichier puis sa
description, sans auteur ni date (l'historique Git les porte). Certains formats n'acceptent
aucun commentaire.

## Décision

- L'en-tête est obligatoire sur les fichiers `.cs`, `.csproj`, `.props`, `.ts`, `.tsx`,
  `.css`, `.mjs`, `.html`, `.md`, `.ps1`, `.cmd`, `.bat`, `.yml`, `.yaml`, `.sql`, `.editorconfig`, `.gitignore`, `.gitattributes` (et `.yaml`), dans la syntaxe
  de commentaire du format : ligne 1 le nom exact du fichier, ligne 2 sa description.
- Les fichiers JSON (`package.json`, `appsettings*.json`, schémas JSON) n'acceptent pas de
  commentaire : ils sont exemptés.
- Code généré exclu, au sens étroit de `RepositoryFiles.IsGenerated` (ADR 037 point 9) : les dossiers que possède un
  outil (`src/Topogenia.Host/wwwroot/`, `web/src/api/generated/`, captures de la maquette) ; dans les migrations d'un
  fournisseur, un `*.Designer.cs` ou l'instantané du modèle dont la première ligne est l'en-tête de l'outil
  (`// <auto-generated`), et une migration que `dotnet ef` a écrite en entier. Un `*.g.cs` ou un `*.Designer.cs`
  ailleurs, ou sans cet en-tête, est un fichier écrit à la main et porte l'en-tête de deux lignes (porte P3, round 3).

## Conséquences

- Tout fichier se reconnaît à sa première ligne, même copié hors du dépôt.
- Le contrôle de format couvre aussi l'UTF-8, l'absence d'emoji et les fins de ligne CRLF des
  fichiers `.bat` et `.cmd`.
