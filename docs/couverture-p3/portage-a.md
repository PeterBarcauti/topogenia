# Couverture phase 3, P3-T07 partie A : concurrence, garde-fous, aller-retour et tests portés

Préfixe des tests : `Topogenia.Persistence.Tests.` ; chaque test est une théorie exécutée sur SQLite **et** SQL
Server (`EngineKind`), sauf `Guards.DatabaseShapeTests.Both_providers_map_one_model_with_the_same_tables_columns_keys_indexes_and_guards`
(un seul fait qui compare les deux moteurs) et `Guards.DatabaseShapeTests.Every_theory_of_the_persistence_that_takes_an_engine_runs_on_both_engines`
(sans base). Nouveaux dossiers : `Concurrency/` (opérations réellement simultanées : plusieurs tâches lancées
ensemble, chacune dans sa propre `IUnitOfWork.RunAsync`, sur le même projet), `Guards/`, `Porting/`, `RoundTrips/`.
À reporter dans `docs/couverture.md` : la colonne « Test 2.0 » reçoit les tests ci-dessous en plus de ceux déjà
cités, la colonne « État » la valeur indiquée. « Mutation » donne une mutation du code qui fait échouer le test
(vérifiée sur une copie privée du dépôt).

Concurrence et moteurs : en SQL Server (lecture validée) deux unités sans verrou de projet lisent toutes deux avant
d'écrire, la course a vraiment lieu (le test l'exige) ; en SQLite les transactions d'écriture sont immédiates, deux
unités ne se rencontrent jamais et s'exécutent l'une après l'autre. Une mutation qui retire le verrou de projet ou le
nouvel essai de l'ADR 033 ne fait donc échouer que la variante SQL Server : c'est le comportement attendu.
